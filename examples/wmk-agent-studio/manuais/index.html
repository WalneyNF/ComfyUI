// 02 CONCEITOS

Como as peças se relacionam?

SEU NAVEGADOR
    |
    +-- WMK Agent Studio :8765
    |       |
    |       +-- Ollama :11434  [modelo de texto local]
    |       |
    |       +-- Groq / OpenAI [modelo de texto na nuvem]
    |
    +-- ComfyUI :8188 [motor de imagens em CPU]
              ^
              |
         comfy-cli
              ^
              |
         comfy-mcp [ferramentas para agentes]

O chat recebe perguntas e mostra respostas. O Ollama executa o modelo de linguagem. O Groq oferece modelos remotos, normalmente mais rápidos para texto. O ComfyUI executa grafos de geração de imagens. O MCP é um protocolo para que agentes descubram e chamem ferramentas externas.

Na versão atual, o botão Gerar imagem do chat chama diretamente a API do ComfyUI. O agente agora pode propor a ferramenta gerar_imagem via tool calling Ollama/Groq. A execução exige autorização no chat. O envio é realizado diretamente pela API do ComfyUI, não via MCP.

// 03 INICIALIZAÇÃO

Como ligar os serviços

1. Inicie o Ollama

Abra um PowerShell e execute:

& 'D:\Ollama\ollama.exe' serve

Se aparecer “address already in use”, provavelmente o Ollama já está ligado. Confira no navegador /api/tags. Ele deve retornar JSON com os modelos disponíveis.

2. Inicie o WMK Agent Studio

Dê dois cliques no arquivo D:\Ferramentas\WMK-Agent-Studio\INICIAR-WMK.bat. Alternativamente:

cd D:\Ferramentas\WMK-Agent-Studio
python server.py

Abra http://127.0.0.1:8765. Mantenha o terminal aberto enquanto usa o chat.

3. Inicie o ComfyUI

Em outro PowerShell:

& 'D:\IA-Local\ComfyUI\venv\Scripts\python.exe' 'D:\IA-Local\ComfyUI\main.py' --cpu --listen 127.0.0.1 --port 8188

O carregamento pode demorar. Aguarde a mensagem “Starting server” e abra http://127.0.0.1:8188.

Os três serviços usam portas diferentes e podem ser iniciados separadamente. Para testar apenas o chat, o ComfyUI não precisa estar ligado.
// 04 TESTE PRÁTICO

Seu primeiro chat com IA local

  1. Abra o WMK Agent Studio.
  2. Clique em Nova conversa.
  3. Em Provedor, escolha Ollama Local.
  4. Clique em ↻ para consultar os modelos instalados.
  5. Escolha qwen2.5-coder:3b, o menor dos três modelos encontrados.
  6. Em Agente, escolha WMK Assistente.
  7. Digite: Responda somente: WMK Studio conectado.
  8. Pressione Enter ou clique em Enviar.

O teste automatizado já recebeu a resposta “WMK Studio conectado.”. A primeira resposta após iniciar o Ollama pode demorar porque o modelo precisa ser carregado na RAM.

// 05 PERSONALIZAÇÃO

Como criar e usar agentes

  1. Abra a aba Agentes no menu lateral.
  2. Clique em Novo agente.
  3. Informe o nome, a especialidade e um prompt de sistema.
  4. Salve e volte para uma conversa.
  5. Selecione o agente criado na barra superior.

Exemplo de prompt para um agente de desenvolvimento:

Você é um desenvolvedor sênior especializado em
Python, JavaScript e arquitetura modular.
Responda em português do Brasil.
Explique o raciocínio técnico, mostre exemplos
executáveis e destaque riscos de segurança.

O agente é um conjunto de instruções para o modelo; ele não possui acesso automático ao seu computador, à internet ou a ferramentas MCP. Esses recursos precisam ser implementados e autorizados separadamente.

// 06 PROVEDORES REMOTOS

Como testar Groq e outros provedores

  1. Obtenha uma chave de API no serviço do provedor, respeitando as condições de uso.
  2. No WMK Agent Studio, abra Provedores e modelos.
  3. Clique em Configurar no cartão Groq.
  4. Confira a URL base https://api.groq.com/openai/v1.
  5. Informe sua chave no campo apropriado e salve.
  6. Volte ao chat, selecione Groq e clique em ↻ para consultar modelos disponíveis.
  7. Escolha um modelo da sua conta e envie uma mensagem curta.
Segurança: na versão atual, as chaves são guardadas em data/studio.json sem criptografia. Não envie esse arquivo a ninguém, não publique no Git e não exponha o servidor local na internet. Nunca coloque chaves no texto das mensagens.

Para outros serviços compatíveis com a API OpenAI, crie um novo provedor, escolha OpenAI compatível e informe a URL base e o modelo. A compatibilidade varia conforme o serviço.

Nova função: no WMK Agent Studio, clique em Gerar imagem, descreva a cena, selecione 256 × 256 e 8 ou 10 steps, confirme e aguarde. O aplicativo envia o workflow ao ComfyUI e tenta exibir a imagem quando a execução termina. O envio do primeiro workflow foi confirmado; a conclusão da geração ainda está sendo validada.
// 07 COMFYUI CPU

Como testar o ComfyUI separadamente

  1. Inicie o ComfyUI conforme a seção 03.
  2. Abra a interface ComfyUI.
  3. Verifique se a página mostra o editor de nós e não um erro de conexão.
  4. Abra /system_stats em outra aba.
  5. Procure pytorch_version e devices. No teste realizado, o dispositivo foi cpu.
  6. Confirme se o checkpoint v1-5-pruned-emaonly.safetensors aparece no nó de carregamento de modelo.

O checkpoint está localizado em D:\IA-Local\ComfyUI\models\checkpoints, com aproximadamente 4 GB. Ele é um modelo da família Stable Diffusion 1.5.

O que fizemos com comfy-mcp?

O fork foi instalado em D:\Ferramentas\comfy-mcp, com ambiente Python independente. O comfy-cli foi instalado e conseguiu consultar o ComfyUI ativo.

O arquivo wmk-mcp-config.json contém um exemplo de registro para clientes MCP compatíveis. O servidor MCP é executado por um cliente via stdio, não possui uma interface de chat própria.

Comando de teste da CLI

Esse comando já foi testado com sucesso. Ele mostra os dados reais do ComfyUI. Para que um agente execute ferramentas, será necessário conectar um cliente MCP e implementar permissões e confirmação de ações.

// 11 SUPORTE

Diagnóstico e soluções

O chat não abre

Confirme se python server.py está em execução e se a porta 8765 está livre. Abra /api/health; deve aparecer JSON com ok: true.

Ollama não conecta

Execute ollama serve e abra /api/tags. Se houver erro de porta ocupada, verifique se já existe uma instância em execução.

Modelo não aparece

Clique em ↻ na barra do chat. Confira os modelos com ollama list. Verifique se o nome selecionado corresponde ao modelo instalado.

Resposta demora

Ollama pode estar carregando o modelo na RAM. Use o modelo 3B e feche aplicativos pesados. O chat atual não mostra tokens em streaming: a resposta aparece quando termina.

ComfyUI não abre

Espere a mensagem de servidor iniciado no terminal. Verifique se a porta 8188 está livre e se não há erros de dependências. Não instale CUDA: o ambiente foi configurado para CPU.

Erro de memória

Reduza resolução, batch e quantidade de tarefas. Evite manter um modelo Ollama de 7B carregado enquanto gera imagens.

Groq responde HTTP 401 / 429

401 geralmente indica problema de autenticação. 429 indica limite de taxa ou quota; consulte as condições da sua conta. Não faça repetição automática agressiva.

├── server.py           # API HTTP, provedores e persistência

├── data\
│   └── studio.json     # estado local e credenciais
└── manuais\
    ├── MANUAL-PTBR.md
    └── index.html

O backend usa a biblioteca padrão do Python. A rota GET /api/state retorna estado sem expor chaves; GET /api/models/{id} consulta modelos; POST /api/chat conversa com o provedor; POST /api/save salva entidades; POST /api/delete exclui registros.

As chamadas de chat são síncronas e não fazem streaming. O histórico é persistido em JSON; para evolução multiusuário, prefira SQLite com transações, autenticação e criptografia de segredos. O servidor deve permanecer restrito a localhost.

Prévia do grafo de geração no chat

Antes de autorizar uma imagem, clique em Ver grafo / plano no cartão da ferramenta. O sistema mostra os sete nós da geração SD 1.5, as conexões, prompt, checkpoint, resolução e sampler. Clique em Salvar workflow JSON (API) para exportar uma versão com seed fixa para reprodução. O grafo é uma visualização própria e simplificada; não é o editor de nós nativo do ComfyUI. O workflow exportado usa o formato da API do ComfyUI, diferente dos JSONs salvos pela interface gráfica. Na geração real a seed é aleatória.
