Leia primeiro: instalar um LoRA na pasta não significa que ele está ativo. O workflow precisa ter o nó LoraLoader ligado ao checkpoint e ao CLIP. O WMK Agent Studio deve ter suporte explícito a essa conexão. Este guia não afirma que o LoRA baixado já foi ativado ou testado.

1. O que é um modelo de IA?

Um modelo é um conjunto de parâmetros numéricos (pesos) aprendido durante treinamento com muitos exemplos. No gerador de imagens, esses pesos permitem produzir novas imagens a partir de instruções e ruído. Ele não funciona como uma biblioteca que simplesmente copia uma imagem pronta. Um modelo-base é a arquitetura e os pesos principais; uma família (SD 1.5, SDXL etc.) define compatibilidades importantes.

Checkpoint é um arquivo ou conjunto de arquivos que guarda o estado treinado do modelo. No SD 1.5, um checkpoint completo normalmente fornece o modelo de difusão, um codificador de texto CLIP e um VAE. LoRA (Low-Rank Adaptation) é um conjunto menor de ajustes que modifica o comportamento de um modelo-base, como ensinar um estilo visual. Ele não substitui o checkpoint principal. Embedding é um recurso de condicionamento textual treinado; VAE transforma latentes em pixels e vice-versa; ControlNet usa controles estruturais como poses ou contornos; upscaler aumenta a resolução, com limitações.

Analogia: checkpoint = artista com repertório; LoRA = especialização em pixel art; prompt = briefing; sampler = método de execução; seed = ponto de partida aleatório; VAE = conversor da representação interna para imagem.

LoRA não é um modelo de linguagem

Ollama executa modelos de linguagem que interpretam seu pedido; o ComfyUI executa modelos de imagem. O agente pode escrever prompts, mas quem gera os pixels é o ComfyUI.

3. Onde encontrar modelos e como escolher

Hugging Face — modelos e Civitai — modelos de imagem. Busque termos como SD 1.5 pixel art LoRA, SD 1.5 RPG character, sprite character LoRA, 2D game assets.

  1. Confirme o tipo: checkpoint, LoRA, embedding ou outro.
  2. Confirme a base: um LoRA SDXL não deve ser aplicado diretamente ao checkpoint SD 1.5.
  3. Leia a model card: objetivo, exemplos, trigger words, limitações, versão e parâmetros sugeridos.
  4. Leia a licença: uso comercial, redistribuição e restrições variam por modelo. Para jogos comerciais, esse passo é essencial.
  5. Confira o tamanho, integridade, reputação do autor e se o download é o arquivo certo.
  6. Compare imagens de exemplo e veja se foram usadas ferramentas adicionais ou pós-processamento.

Exemplo para estudar: r3lax/pixel-art-LoRa. Antes de usar, confira a compatibilidade, a licença e instruções atuais na página original. Não assuma que qualquer LoRA gera automaticamente spritesheets animados.

4. Instalação no seu ComfyUI — passo a passo

  1. Baixe um LoRA compatível com seu checkpoint.
  2. Copie o arquivo .safetensors para D:\IA-Local\ComfyUI\models\loras\.
  3. Mantenha o checkpoint principal em D:\IA-Local\ComfyUI\models\checkpoints\.
  4. Reinicie o ComfyUI ou atualize os modelos.
  5. Abra o ComfyUI, adicione Load LoRA e escolha o arquivo.
  6. Conecte a saída MODEL do checkpoint à entrada model do LoRA e a saída CLIP à entrada clip.
  7. Use as saídas do LoRA no KSampler e nos dois nós CLIPTextEncode.
  8. Experimente força 0,7 em strength_model e strength_clip; ajuste conforme documentação e resultado.
Teste obrigatório: faça uma imagem com LoRA desativado (forças 0) e outra com 0,7, mantendo prompt, seed, steps, CFG, sampler e resolução idênticos. Assim você identifica o efeito real do LoRA.

Não existe configuração universal. SD 1.5, SDXL e modelos rápidos/distilados podem exigir valores diferentes. Para um teste controlado, altere um parâmetro por vez.

6. Como funciona o grafo com LoRA

CheckpointLoaderSimple
       ├── MODEL ──┐
       ├── CLIP ───┤──→ LoraLoader ── MODEL ──→ KSampler
       └── VAE ───┘          │
                            └── CLIP ──→ CLIPTextEncode (+) ──┐
                                      └→ CLIPTextEncode (-) ──┤
EmptyLatentImage ──────────────────────────────────────────────┤
                                                              ▼
                                                           KSampler
                                                              │
                                                       VAEDecode ← VAE
                                                              │
                                                           SaveImage

O LoraLoader recebe MODEL e CLIP, aplica os ajustes e devolve versões modificadas. Os prompts positivo e negativo são convertidos em condicionamentos. O KSampler gera um latente, o VAE o decodifica, e o SaveImage grava PNG. O grafo do WMK precisa incluir o nó LoRA para usá-lo; copiar o arquivo não muda o pipeline automaticamente.

JSON: dois formatos diferentes

O JSON de workflow visual contém posições de nós e links do editor. O JSON de API contém class_type, inputs e referências entre nós. O WMK utiliza JSON de API para executar. Nenhum desses arquivos é o próprio modelo.

{
  "8": {
    "class_type": "LoraLoader",
    "inputs": {
      "lora_name": "WMK_PixelArt_SD15.safetensors",
      "strength_model": 0.7,
      "strength_clip": 0.7,
      "model": ["1", 0],
      "clip": ["1", 1]
    }
  }
}

Este trecho é ilustrativo; ele precisa ser integrado a um workflow completo com ligações corretas.

7. Tutorial: personagem 2D para jogos

  1. Defina o estilo: pixel art 16-bit, cartoon, anime ou pintura digital.
  2. Escolha checkpoint e LoRA compatíveis com esse estilo.
  3. Defina um prompt com corpo inteiro, pose, vista, roupas, paleta e fundo simples.
  4. Gere uma imagem de referência e revise anatomia e silhueta.
  5. Para consistência, mantenha seed e prompt-base, mas não espere identidade perfeita apenas com isso.
  6. Crie vistas e poses separadas usando referência visual/controle de pose quando possível.
  7. Remova fundo com ferramenta adequada, revise transparência e bordas.
  8. Recorte quadros e normalize tamanho, alinhamento e ponto de apoio.
  9. Monte spritesheet e teste a animação no jogo.

Prompt de exemplo

pixel art, full body fantasy RPG warrior, standing idle,
front view, black plate armor, flaming sword, 16-bit game
sprite, readable silhouette, centered, simple plain background

Negativo: blurry, extra arms, extra legs, watermark, text, cropped body, complex background.

Limitações: texto→imagem não produz necessariamente fundo transparente, grade perfeita, direção consistente ou animação utilizável. Para produção profissional, combine geração com edição e revisão manual.

8. Problemas frequentes e solução

SintomaCausa possível / teste
LoRA não apareceArquivo na pasta errada, atualização pendente ou extensão incorreta; reinicie e confira lista
LoRA não muda imagemNó não conectado, força zero, modelo-base incompatível ou trigger word ausente
Imagem feiaCheckpoint inadequado, prompt vago, resolução pequena, sampler ou LoRA mal ajustado
Personagem cortadoPrompt/enquadramento inadequados; peça full body e mais espaço ao redor
Imagem demoraCPU, resolução, steps, memória e tamanho do modelo
Erro de memóriaReduza resolução, lote e complexidade; feche outros processos
Não consigo reproduzirSeed, modelo, LoRA, versão, sampler, scheduler e parâmetros precisam coincidir
Licença desconhecidaNão assuma permissão comercial; leia os termos originais

Exercícios

  1. Explique com suas palavras a diferença entre checkpoint e LoRA.
  2. Identifique qual nó recebe o prompt positivo e qual recebe o negativo.
  3. Gere dois resultados com seed fixa e forças de LoRA 0 e 0,7.
  4. Compare dois samplers sem alterar os demais parâmetros.
  5. Registre modelo, licença, prompt, seed, steps, CFG e imagem final em um JSON de experimento.
